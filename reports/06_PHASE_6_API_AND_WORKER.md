# Отчет Фазы 6: Серверная Архитектура, Очередь Задач и API

## 1. Обзор Реализации
* **Модули:**
  - `src/viral_clips/services/pipeline_service.py` — сервис оркестрации стадий с распределением весов прогресса.
  - `src/viral_clips/api/app.py` — REST API на базе FastAPI.
* **Соответствие спецификации `05_API.md`:**
  - `POST /v1/projects` — создание проекта с параметрами языка и желаемого количества клипов.
  - `GET /v1/projects` & `GET /v1/projects/{id}` — получение списка проектов и детальной информации с вложенными клипами.
  - `DELETE /v1/projects/{id}` — мягкое удаление проекта (`deleted_at`).
  - `POST /v1/projects/{id}/upload` — загрузка видеофайла напрямую в локальное/облачное хранилище.
  - `POST /v1/projects/{id}/process` — запуск фоновой задачи обработки видео (возвращает статус `202 Accepted` и `job_id`).
  - `GET /v1/jobs/{id}` — опрос текущего статуса задачи.
  - `GET /v1/jobs/{id}/events` — стриминг событий в реальном времени через **Server-Sent Events (SSE)**.
  - `POST /v1/jobs/{id}/cancel` — безопасная отмена запущенной задачи.
  - `GET /v1/projects/{id}/candidates` — получение списка всех кандидатов с разбивкой по 7 измерениям виральности.
  - `POST /v1/candidates/{id}/accept` — подтверждение кандидатов пользователем.
  - `GET /v1/renders/{id}/download` — скачивание готового вертикального MP4 клипа.
* **Формат ошибок:** Соответствует стандарту RFC 7807 (Problem Details) с полями `code`, `message`, `details`, `request_id`.
* **Фоновый пул воркеров:** `ThreadPoolExecutor` с контролем параллелизма (по умолчанию 1 воркер для безопасной работы с 8 ГБ VRAM RTX 4060).

## 2. Критерии приемки (Gate Phase 6)
- [x] Полный набор эндпоинтов согласно ТЗ.
- [x] Реактивный стриминг прогресса через SSE (0–100%).
